# Bug Hunt Findings — 2026-06-09 (second sweep)

Date: 2026-06-09. Method: multi-agent hunt (10 hunters over decontaminated logs,
code audits of the Inject/Speech/App modules, and the persisted correction store),
every finding adversarially verified by two independent agents (evidence-source
lens + mechanism lens; both had to confirm), then a completeness critic. 17
findings confirmed, 6 refuted, 0 left uncertain. Supersedes nothing — the prior
triage (`specs/open-bug-leads.md`) is fully closed; do not re-triage it.

P2 = degraded but recoverable, P3 = latent hazard not yet observed in real usage.

   `app=nil` or missing `recordingID=` as test output.** Raw `focusChanged` abort

   effect once built. The 30 "dropped 1 undecodable record(s)" errors and the one

3. Genuine real-usage focus-abort evidence lives in coordinator-side

## P1 — open

### 1. Transient AX unresponsiveness aborts the whole dictation (speech lost) — OBSERVED

The one new P1, found by code audit and then confirmed against real usage by the
completeness critic: **3 real sessions on 2026-05-31 lost nearly the entire
utterance** (3 of 40, 3 of 72, 4 of 95 chars inserted).

- Mechanism: `focusChangedSinceStart()` treats any `nil` from
  `copyFocusedElement()` as a focus change (`InsertionTargetGuard.swift:279-284`);
  `copyFocusedElement` collapses every non-`.success` AXError to `nil`
  (`:487-497`), including `kAXErrorCannotComplete`, which the SDK header documents
  as "the accessible application is unresponsive or waiting for user input" under
  the 0.25s messaging timeout set at `:251`. Result maps to `.focusChanged` →
  always `.abort` → `cancel()` (`ProgressiveTranscriptInsertion.swift:159-164`).
  No identity-pin or one-sided-nil tolerance exists on this path (the `:184`
  escape only covers value-read aborts).
- Evidence of real harm: all 3 sessions abort exactly ~253ms after the first
  `typed` line (the second AX read), then the transcript keeps growing with zero
  further insertions — e.g. 11:42:46.546Z `typed 4 chars` → 46.799Z "focused
  element unreadable mid-session; treating as focus change" → final 95 chars,
  nothing more typed. A fixed ~253ms gap across all three is an AX stall, not a
  human moving focus three times. Code path is byte-identical at HEAD.
- Root enabler: every AX read helper in the module discards the AXError
  (`InsertionTargetGuard.swift:351,360,369,384,394,423,431,443,484,492`); nothing
  can distinguish transient (`cannotComplete`/`apiDisabled`) from permanent
  (`invalidUIElement`).
- Fix direction: surface the AXError from `copyFocusedElement`; treat a transient
  messaging failure as "unknown, not changed" (mirror the one-sided-nil principle
  at `InsertionTargetFocusSignature.swift:51-55`), optionally one bounded retry.
  Not unit-testable (AX I/O) — verify by long dictation into an app under load.

## P2 — open

### 2. Bootstrap-failure latch replay silently drops a held-fn dictation (latent)

On first launch / TCC reset / failed asset download, `bootstrap()` can finish with
`captureFormat == nil`: `_ = await assets.prepare()` discards a `.failed` result
(`AppCoordinator.swift:216-225`, `AssetManager.swift:81-85`), and the replay then
hits the drop branch at `AppCoordinator.swift:234-237` — error log only, no UI.
The user held fn, spoke, and gets zero indication. Never fired in real usage (this
machine has permissions/assets pre-granted; the only occurrence is a test
fixture). Fix: surface user-visible feedback on the drop and stop discarding
`assets.prepare()`'s status. Repro: `tccutil reset Microphone com.steez.Epos`,
hold fn at launch.

### 3. Evidence store: empty-string AX re-reads stored as user edits

5 of 13 persisted evidence records carry `userEditedTranscript=""` against a
non-empty final (recIDs 61f12f83, 190a817c, cf3e68db, d6a79c2e, c6d159d8).
`recordUserEdit` only guards `final != edited`, so an empty AX read-back (field
cleared / focus moved / opaque) passes and overwrites the real nil signal
(`CorrectionEvidence.swift:88-97`, fed from `AppCoordinator.swift:606-614`).
The suggester discards them, so no bad alias results — but the records are
permanently mislabeled. Fix: skip `recordUserEdit` when the observed text trims
to empty. Distinct from the known "burst dictation under-collects" design note:
this *writes false positives*, it doesn't under-collect.

### 4. Evidence store: truncated mid-edit AX read produced the only suggestion candidate

Record 7dae3556 (2026-06-04): the edit-capture timer read the field while the
user was mid-edit, capturing the truncated prefix "is using the onh hand quantity
of " (typo + trailing NBSP, cut mid-sentence) as the "edit" of a 16-word final.
`CorrectionPhraseDiff.replacement` turns that into a nonsense alias
(`'on-hand quantity of today / live …' → 'onh hand quantity of'`). Only the
gate's `minimumPositiveEvidenceCount=2` blocks it today. Fix family: settle the
observe window, or reject edits that are a strict truncation prefix of the final
(a deletion, not a correction).

### 5. Accuracy: lowercase-canonical rules destroy sentence-initial capitalization

`replacingMatches` inserts `spec.canonical` verbatim with a case-insensitive
alias regex (`TranscriptCanonicalizer.swift:222`, `CorrectionMatchContext.swift:15`).
Verified against the real module: `"Code base needs a refactor."` →
`"codebase needs a refactor."`. Any lowercase canonical that can open a sentence
(codebase, unslopify, …) downcases the recognizer's capital. Fix: when the match
is sentence-initial and the source began uppercase, uppercase the canonical's
first character. Test: `'Code base …' → 'Codebase …'`.

## P3 — open (latent; none observed in real usage)

### 6. Fallback final under append-only latch drops re-cased trailing words

`acceptFallbackFinalTranscript` passes
`lossProofAppend: target.hasPrefix(committedText)`
(`ProgressiveTranscriptInsertion.swift:74`); a real segment final passes `true`
(`:62`). Under the append-only latch, a fallback final that re-cased an earlier
word while extending it (committed `"the door"`, fallback `"The door is open"`)
fails the byte-prefix test and inserts `""` — trailing words dropped — while the
identical text through the final path recovers them via `lossProofAppendTail`.
Repro'd in a standalone swift script. Logs show 217 real append-only latches and
7 real fallback promotions but never both together, so unobserved. Fix: pass
`lossProofAppend: true` unconditionally at `:74` — `lossProofAppendTail` already
enforces the safety the byte-prefix check was for (verified against the input of
`testAppendOnlyFallbackFinalDoesNotGraftUnsafeNonPrefixTail`). Add the mirror
test ending with the fallback call.

### 7. Empty-string value read with non-empty baseline bypasses the reflection classifier

`InsertionTargetObservation.read` (`InsertionTargetGuard.swift:119-126`) routes
`value==""` + non-empty baseline context to `.positionedValue("",…)` instead of
the `hasReflectedText`-keyed `.notRead`/`.emptyExposed` a `nil` read gets. Does
NOT reopen the cmux fix (cmux's baseline context is empty → still `.notRead`);
currently non-harmful because affected native fields have
`verifiesFocusIdentity()==true` so the abort is absorbed into append-only.
Fix: require `!value.isEmpty` for the positionedValue branch; add the
`read("", …) == .notRead` test mirroring the nil case.

### 8. `finish()` can hang when finalize fails: drain cancel can't unblock Apple's stream

The catch path cancels `drainTask` then still awaits `drainTask.value`
(`Transcriber.swift:189-199`), but the drain is `for try await result in
transcriber.results` with no cancellation handler (`:84-92`) — `cancel()` cannot
unblock a suspend inside Apple's opaque AsyncSequence. Zero `finalize failed`
lines in any log; pure latent. Fix: timeout-race the drain await, or make the
failed-finalize path fire-and-forget like the no-input branch (`:200-209`).

### 9. Non-empty finalize path has no wall-clock bound

`finishRecording`'s only loop terminator is `Task { await transcriber.finish() }`
(`AppCoordinator.swift:329`); `finalizeAndFinishThroughEndOfInput`
(`Transcriber.swift:188`) has no timeout. If Apple's finalize hangs without
throwing, the coordinator sticks in `.finalizing` forever and every later fn
press is dropped; recovery = app restart. The empty-input path already has an
escape (`:173,201-208`); the with-input path needs the equivalent. All 204 real
sessions completed (logs balanced 470/470/470), so latent. Fix: timeout race +
promote last partial; unit-test with a fake analyzer whose finalize never returns.

### 10. `start()` can return a dead event stream if a concurrent `finish()` wins

`start()` installs the session, awaits, then returns `eventStream` unconditionally
(`Transcriber.swift:116-137`); a racing `finish()` nils the session and closes the
continuation, and the caller gets a finished stream with no error. Safe today only
because `AppCoordinator.runSession:347` re-checks `state == .recording`. Fix:
re-check the session after the await and throw, so the contract is self-contained.

### 11. Accuracy: alias word boundaries are ASCII-only

`CorrectionMatchContext.swift:14` uses `(?<![A-Za-z0-9])…(?![A-Za-z0-9])`; an
accented neighbor doesn't count as a word character (`'caféepos'` → alias fires
mid-word, verified). Fix: `(?<![\p{L}\p{N}])` / `(?![\p{L}\p{N}])`.

### 12. Accuracy: dash-dash flag pre-pass greedily prefixes any following word

`attachingFlagPrefix` rewrites `dash dash <word>` → `--<word>` unconditionally
(`TranscriptCanonicalizer.swift:233-251`): `'just dash dash here'` → `'just
--here'`. Documented design tradeoff (`:243-247`), so only act if dogfood shows
real false positives (confirm frequency with `EPOS_DIAGNOSTIC_TRANSCRIPT_TEXT=1`).

### 13. Finalize-window replay can spawn a ~161ms phantom session

`pendingStartWhileFinalizing` replay fires when fn reads held at the
`.finalizing → .idle` transition (`AppCoordinator.swift:756`) — including while
the user is mid-release. One real case (2026-05-31T16:07:04): 161ms capture,
`results=0`, `finalChars=0`. No data loss; optional debounce.

### 14. Test fake models deletes in UTF-16 units; production deletes graphemes

`FieldBackedRecordingBackend.recordDelete`
(`InsertionTargetGuardTests.swift:1607-1620`) applies the delete count as a
UTF-16 offset; production presses delete once per grapheme
(`TextInsertionBackend.swift:80`), and `GuardRecordingBackend` (the other fake)
is grapheme-correct. ASCII-only tests hide it today; a future non-ASCII
regression test would pass falsely. Live-path math was independently audited
clean (guard caret math is UTF-16 vs UTF-16, insertion math grapheme vs
grapheme). Fix the fake or mark it ASCII-only.
