## First fixes

| Priority | Defect and evidence | Change |
| --- | --- | --- |
| P1 | Native NSTextView reproduction showed that preview over selected `world` followed by cancellation changed `hello world` to `hello ` | Skip preview for selected text; companion validates selections and live composition ownership, pins its concrete client, refuses ambiguous client sets, and blocks either final backend after losing live composition ownership |
| P1 | After a socket timeout, a late mark acknowledgement could be mistaken for cancellation, hiding an unsafe cleanup reply | Close unaligned connections, reject malformed framing, and refuse final delivery when required cleanup is unconfirmed |
| P1 | Releasing while analyzer startup was suspended bypassed captured audio and reported cancellation | Stop the mic at release, hand startup audio to the analyzer, then finalize and deliver once |
| P1 | `start()` awaited framework startup without a bound, even when finish timed out | Bound the caller's startup wait and force-close a timed-out session; regression uses a framework stand-in that ignores cancellation |
| P2 | A skipped preview could accept a prior recording's late HUD callbacks | Invalidate preview callbacks at every recording start, including selected-text, disabled, and unidentified-target holds |
| P2 | An old socket thread could execute queued commands against a newer preview pass | Validate current connection ownership immediately before command dispatch and preserve pass ownership through cleanup |
| P2 | `.failed` could leave the result stream open and delay the recognition-loss notice indefinitely | Treat failure as terminal immediately, stop capture, show the notice while held, and preserve recognized text until release |
| P2 | Capture setup or device recovery could fail after enabling voice processing, then skip cleanup because capture was not running | Use the same input-path unwind on successful stop and failed open or recovery |
| P2 | The strict build failed under installed Xcode 27 at the lazy generic View initializer | Explicitly isolate that initializer closure to the main actor |

## Next correctness work

1. **P2, correction evidence can misattribute rules.** The coordinator freezes
   its cleaner at recording start, but
   [CorrectionEvidenceRecorder](../Sources/Epos/App/CorrectionEvidenceRecorder.swift)
   recomputes canonical text and rule IDs using the live dictionary after
   delivery. Editing a rule during a hold can persist evidence for a rule that
   did not produce the delivered text. Capture one immutable correction snapshot
   with rule provenance for both output and evidence. Regress with a rule edit
   between recording start and delivery. Learn corrections defaults off, which
   limits the immediate exposure.
2. **P2, ambiguous IME delivery lacks visible feedback.** A fully sent final
   commit without acknowledgement suppresses a second write correctly, but the
   coordinator reports the ambiguity only in diagnostics. Define an honest
   visible result that asks the user to inspect the field without claiming the
   write failed. Cover an acknowledgement lost after actual insertion.
3. **Integration gate, real target delivery.** Test the current signed app and
   companion in the daily target apps before declaring replacement readiness.
   Native text-view checks and fake AX observers cannot establish Electron,
   terminal, Secure Input, input-method proxy lifetime, microphone switching,
   or permissions behavior.

## Structural work

The new final-delivery safety tests live in their own suite and share transport,
backend, and target doubles with the lifecycle suite. This keeps the existing
test file below 1,000 lines without duplicating its fixtures.

The strongest product simplification is recording ownership. AppCoordinator stores the
transcription task, cleaner, target session, recording ID, reliability recorder,
release waiters, and readiness for audio independently. Several exit paths
manipulate overlapping sets of those resources. A recording session should own
them and return one terminal result. The coordinator can then own readiness,
key state, and published presentation. Preserve the release, failure, deferred
press, and exactly-once delivery tests when changing that boundary.

The correction snapshot also provides a direct simplification. Canonical text
and applied rule IDs should come from one matching pass. Current
[CorrectionDictionaryAppliedRules](../Sources/Epos/Speech/CorrectionDictionaryAppliedRules.swift)
recompiles matching rules separately from the canonicalizer, which makes
provenance drift easier.

The companion is production code inside `probes/`. Its string command and reply
contracts are maintained separately from the app's session state. Keep ownership
and acknowledgement semantics explicit before changing packaging or introducing
a shared protocol. Moving files alone would not fix those contracts.

## Evidence limits and verification

The local diagnostic logs ended August 8, 2026. `scripts/audit` found 407
schema-1 recording starts, including 10 target refusals, six delivery mismatches,
and one incomplete session. These are dated leads, not current defect counts.
The 175 empty transcripts and 28 no-input sessions cannot be labeled lost speech
without inspecting their capture context.

The default saved accuracy artifact contained 114 rows and 106 exact outputs,
but failed its authoritative corpus join. The audit reported
`authoritative_join_mismatch` and `verifiedAccuracy=false`. Those rows cannot
support a current accuracy claim. Select and verify a current signed artifact
and confirmed reference corpus explicitly.

Verification passed the strict Swift build, the Swift suite with 366 tests, three
opt-in evaluation skips and zero failures, SwiftLint without a cache, the complete
signed main-app build, companion compilation with warnings as errors, ten
native safety checks, and deterministic audit, corpus, confirmation, labeling,
and migration checks. Opt-in evaluation skips remain separate from passes. The built app and companion have not been installed or
launched during this review.

The replacement gate is a current signed installation passing the daily-app
matrix in [development.md](development.md#runtime-acceptance), including 50
consecutive recordings and measured latency, startup, and memory. Keep those
measurements separate from recognition accuracy and backend acceptance.
